# Verified Profile, Visibility, and Contacts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enforce the existing-but-dead `Link.revokedAt` and `Link.visibility` columns, gate owned-link creation on `User.emailVerified`, add a friend-request toggle/button, and add real "disappear from view" contact blocking.

**Architecture:** Pure backend enforcement + two small new endpoint families (`revoke`/`unrevoke`/visibility PATCH, `block`/`unblock`) layered on the existing `lib/links.ts` and `lib/contacts.ts` modules, plus three small frontend additions (an account settings toggle, a button on the sender-facing page, and block/unblock controls in the existing contacts UI).

**Tech Stack:** Fastify, Prisma, Vitest (`server.inject`), React, `react-i18next` (existing locale bundle pattern).

**Spec:** `docs/superpowers/specs/2026-09-26-verified-profile-contacts-design.md`

## Global Constraints

- A `contacts-only` or otherwise-inaccessible link returns **404**, never 403 — no response may let a caller distinguish "link exists but you can't see it" from "link doesn't exist" (spec §3.2, §6).
- A blocked user's `sendContactRequest` call must get the byte-identical error shape/message as a genuinely nonexistent username (spec §6).
- The friend-request button on a profile page is **always rendered** (enabled or disabled), never conditionally omitted — its presence must carry no information about `allowContactRequests`'s value (spec §5).
- `POST /api/links/custom` requires `request.user.emailVerified === true`; an unverified authenticated caller gets a clear 403 with an explanatory message, not a silent fallback to anonymous behavior (spec §4).
- Revoke/unrevoke/visibility-PATCH and block/unblock are all real state changes on rows other requests read — every new write here must use the same compare-and-swap discipline already established in this codebase (`transitionDropStatus`/`deleteLinkIfExists` in `apps/api/src/lib/links.ts`) wherever a race is possible.

## Review Focus

- A `contacts-only` link viewed by an **anonymous** (no session) caller — must 404, not treat "no session" as automatically non-matching-but-otherwise-visible.
- A user who blocks someone **they have an accepted contact with** (not just a pending request) — blocking must work from the accepted state too, not only from pending.
- Two different users independently trying to `block` the same relationship row at once, or one blocking while the other simultaneously sends a fresh contact request — the unique `(userId, contactUserId)` constraint must not let a race produce two live rows for the same pair.
- An owner revoking a link that has **no drops at all** — must succeed without error (nothing to shred), not throw on an empty collection.
- `PATCH /api/links/:slug` visibility change called by someone who is **not** the link's owner (including on an anonymous link, which has no owner) — must 403/404, never silently accepted.

```typescript
// Unifies every reason a link should be treated as gone when *served* (as
// opposed to isLinkExpired, which the cleanup job also uses purely for its
// own age-based sweep and must keep meaning "past expiresAt" only).
// Checked wherever a link is read for the purpose of using it — GET
// /api/links/:slug, upload, claim — never for ownership/management routes,
// which an owner must still be able to reach on their own revoked/
// unverified link.
export async function isLinkInactive(link: Link): Promise<boolean> {
  if (isLinkExpired(link)) return true;
  if (link.revokedAt !== null) return true;
  if (link.ownerId !== null) {
    const owner = await prisma.user.findUnique({ where: { id: link.ownerId }, select: { emailVerified: true } });
    if (!owner || !owner.emailVerified) return true;
  }
  return false;
}
```

```typescript
  async function requireOwnedLink(slug: string, userId: string, reply: FastifyReply) {
    const link = await getLinkBySlug(slug);
    if (!link) {
      reply.status(404).send({ error: "Link not found" });
      return null;
    }
    if (link.ownerId !== userId) {
      reply.status(403).send({ error: "Forbidden" });
      return null;
    }
    return link;
  }

  server.post<{ Params: { slug: string } }>(
    "/api/links/:slug/revoke",
    { preHandler: server.requireAuth },
    async (request, reply) => {
      const link = await requireOwnedLink(request.params.slug, request.user!.id, reply);
      if (!link) return;
      await prisma.link.update({ where: { id: link.id }, data: { revokedAt: new Date() } });
      // NOTE (see plan self-review / spec §3.1): shredding this link's still-
      // sealed/delivery_failed drops on revoke is spec 2's job (owner-cancel
      // mechanism) and is intentionally NOT done here — spec 2's plan should
      // add that call once its shred function exists. Revoke here only makes
      // the link stop being servable; it does not touch existing drops.
      return reply.send({ revoked: true });
    }
  );

  server.post<{ Params: { slug: string } }>(
    "/api/links/:slug/unrevoke",
    { preHandler: server.requireAuth },
    async (request, reply) => {
      const link = await requireOwnedLink(request.params.slug, request.user!.id, reply);
      if (!link) return;
      await prisma.link.update({ where: { id: link.id }, data: { revokedAt: null } });
      return reply.send({ revoked: false });
    }
  );

  server.patch<{ Params: { slug: string }; Body: { visibility?: string } }>(
    "/api/links/:slug",
    {
      preHandler: server.requireAuth,
      schema: { body: { type: "object", properties: { visibility: { type: "string" } } } },
    },
    async (request, reply) => {
      const link = await requireOwnedLink(request.params.slug, request.user!.id, reply);
      if (!link) return;
      const { visibility } = request.body;
      if (visibility !== "public" && visibility !== "contacts-only") {
        return reply.status(400).send({ error: "Invalid visibility" });
      }
      await prisma.link.update({ where: { id: link.id }, data: { visibility } });
      return reply.send({ visibility });
    }
  );
```

export async function blockContact(callerId: string, contactId: string): Promise<Contact> {
  const row = await prisma.contact.findUnique({ where: { id: contactId } });
  if (!row) throw new HttpError(404, "Contact request not found");
  if (row.userId !== callerId && row.contactUserId !== callerId) {
    throw new HttpError(403, "Not part of this contact relationship");
  }
  return prisma.contact.update({ where: { id: contactId }, data: { status: "blocked", blockedByUserId: callerId } });
}

export async function unblockContact(callerId: string, contactId: string): Promise<void> {
  const row = await prisma.contact.findUnique({ where: { id: contactId } });
  if (!row) throw new HttpError(404, "Contact request not found");
  if (row.status !== "blocked" || row.blockedByUserId !== callerId) {
    throw new HttpError(403, "Only the user who blocked this contact may unblock it");
  }
  await prisma.contact.delete({ where: { id: contactId } });
}
